### 2026-11-16 — Fix oversized dashboard banner

- User reported the dashboard banner looked "a little bit bigger" than expected. Root cause confirmed against Google's Android AdSize reference and SDK release notes: the previous fix used `AdSize.getLargeAnchoredAdaptiveBannerAdSizeWithOrientation`, the newer **"large" anchored adaptive banner** format Google added in GMA Android SDK v25.0.0 specifically "to increase engagement and revenue" (taller: up to 20% of screen height, 50-150dp). That is visibly bigger than the classic/standard anchored adaptive banner (capped around 15% of screen height, 50-90dp) this app intends to show.
- Fix: `BannerAdWidget` now requests the standard anchored adaptive banner via `AdSize.getAnchoredAdaptiveBannerAdSize`, with a documented, deliberate `// ignore: deprecated_member_use` — that method is marked deprecated purely to steer publishers toward the larger/more-revenue format, not because it stopped working; this app intentionally keeps the smaller, less intrusive size. The already-reserved-space fix from the prior session (no layout shift while loading) is unaffected and still applies, just with the smaller target size.
- Verification: `flutter analyze --no-pub` reports no issues; `dart format` reports no changes; all **335 tests pass** via `flutter test --no-pub --reporter compact`; debug APK builds successfully. No device/emulator visual confirmation of the corrected banner size yet — remains pending alongside all previously logged hardware acceptance.

### 2026-11-16 — Correct ads to current AdMob policy; fix banner layout shift

- Re-checked the previous session's ad implementation against Google's live AdMob policy pages and found two real issues, both now fixed.
- **Policy fix — wrong ad format on app resume:** Google's "Disallowed interstitial implementations" policy (https://support.google.com/admob/answer/6201362) explicitly forbids showing an interstitial "on app load or when exiting apps" and recommends an **app open ad** instead for "shown when loading an app or switching back to it." The previous session's resume handler loaded and showed a plain `InterstitialAd`, which is exactly the disallowed pattern. Replaced it: `AdsService.loadAppOpenAd` now loads Google's test app open unit (`ca-app-pub-3940256099942544/9257395921`, replacing the removed test interstitial unit), and `SpeedometerApp` preloads an `AppOpenAd` at startup, shows it (at most every third return from the background, never on first launch) via `AppOpenAd.show()`/`FullScreenContentCallback`, and reloads the next one after each dismissal/failure, per Google's "preload before showing" and dispose-on-dismiss guidance. `AdUnitIds.androidInterstitial` was removed and replaced with `AdUnitIds.androidAppOpen`.
- **Layout-shift fix — banner popped in from zero height:** Google's banner implementation guidance (https://support.google.com/admob/answer/2936217) requires reserving fixed ad space while a screen loads so ads "do not cover or shift other content to prevent accidental clicks." `BannerAdWidget` previously rendered `SizedBox.shrink()` until the ad fully loaded, then jumped to full banner height, shifting the dashboard's trip controls above it. It now computes and reserves the final adaptive-banner size immediately (before the ad request even starts) and only swaps in the loaded `AdWidget` inside that already-reserved space; a failed load still collapses to zero height, but only before any content could have shifted under the user's thumb.
- **Hidden-functionality check:** reviewed the dashboard's widget tree. `Scaffold.bottomNavigationBar` reserves space above itself for `body` automatically (confirmed via the existing `SafeArea`/`ListView` structure) and does not overlay or cover any dashboard button, so no functionality was actually hidden by the banner; the real defect was the height jump above, not something irreversibly hidden.
- Verification: `flutter analyze --no-pub` reports no issues; `dart format` reports no further changes; all **335 tests pass** via `flutter test --no-pub --reporter compact`; debug APK builds successfully. Release App Bundle was not rebuilt this session (unchanged dependency versions; prior session's 56.8 MB AAB remains the latest built artifact). Limitation: still no device/emulator run has exercised the app open ad or the reserved-space banner visually; this remains pending alongside all previously logged hardware acceptance. The Play Console Ads declaration, data-safety form and privacy-policy disclosure obligations noted in the prior entry are still outstanding.
